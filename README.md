# 报告查验二维码系统

报告上印二维码，扫码后打开移动端查验页：版式为「机构标识 → 检测报告在线查验横幅 → 报告编号输入 → 查询 → 查验结果」。

- 二维码指向：`https://<域名>/v/<报告编号>?k=<签名>`
- 签名是 HMAC，只有签发端（持有 `config.json` 里的 secret）能生成，扫码端只能验证。
- 也可以手动输入报告编号查询（`/?no=<编号>`）。

## 两种部署方式

| 方式 | 需要 | 适合 |
|---|---|---|
| 动态服务 `app.py` | 服务器 / 云主机 | 报告库经常变动，需要签名校验 |
| 静态站 `build_static.py` | 只要托管（GitHub Pages 等） | 报告数量可控，零成本上线 |

静态站见 [GITHUB.md](GITHUB.md)，服务器部署见 [DEPLOY.md](DEPLOY.md)。

## 文件

```
report-verify/
├─ app.py            动态查验服务（标准库，无第三方依赖）
├─ build_static.py   生成 GitHub Pages 用的静态站 docs/
├─ pages.py          两种模式共用的页面模板
├─ make_qr.py        动态版：生成带签名二维码
├─ qrcodegen.py      纯 Python 二维码编码器
├─ render.py         二维码渲染成 PNG
├─ sign.py           签名 / 验签
├─ config.json       机构信息、域名、密钥
├─ reports.json      报告库
├─ qr/               生成的二维码
├─ docs/             静态站（build_static.py 生成）
└─ _*.py             开发期自检脚本，可删
```

## 运行

```powershell
python app.py --host 0.0.0.0 --port 8787   # 手机要访问就必须绑 0.0.0.0
python make_qr.py --base-url https://你的域名   # 生成正式二维码
```

页面：

| 地址 | 用途 |
|---|---|
| `http://<本机IP>:8787/` | 查验页，可手动输入报告编号 |
| `http://<本机IP>:8787/qr` | 把二维码放大显示，方便用手机扫屏幕 |
| `http://<本机IP>:8787/v/<编号>?k=<签名>` | 扫码后打开的地址 |

## 关于扫码

手机扫二维码能打开，前提是二维码里的地址手机能访问：

- `http://127.0.0.1:8787/...` 在手机上指向手机自己，微信打不开——所以生成二维码时 `base_url` 不能是 127.0.0.1。
- 测试用局域网地址 `http://192.168.x.x:8787`，手机需与电脑同一 WiFi；若打不开，多半是 Windows 防火墙拦了 8787 端口，允许 Python 入站即可。
- **要让全世界任何人扫码都能打开，必须部署到公网域名**，见 [DEPLOY.md](DEPLOY.md)。

## 二维码为什么不容易被仿

1. `k` 是报告编号的 HMAC 截断值，复制二维码到另一份报告上，编号对不上，页面判「校验未通过」。
2. 没有密钥签不出有效链接。
3. 页面顶部显示机构名称与标识，域名栏由浏览器显示——用户能看出是否在官方域名上。

这些只能证明链接由本机构签发，纸质报告本身仍需与页面信息逐项核对。

## 上线前必须改

| 项 | 位置 | 说明 |
|---|---|---|
| `service.base_url` | `config.json` | 改成官方 HTTPS 域名 |
| `service.secret` | `config.json` | 换成长随机串，只放服务端 |
| `reports.json` | 数据 | 换成真实报告库 |
| 部署 | — | 必须部署在本机构自己的域名与服务器上 |

## 数据结构

```json
{
  "报告编号": {
    "sample_name": "样品名称",
    "model": "型号规格",
    "client": "委托单位",
    "category": "检验类别",
    "issued": "2026-03-06",
    "conclusion": "检测结论"
  }
}
```
